## 这是什么

一套跑在 tmux 里的 Claude Code 管理工具，四块东西合在一起用：

- **底栏**：所有会话的状态一直挂着——谁在等你（`⏸`）、谁做完了你还没看（`✔`）、谁在跑（`▶`）；
  右边是整机 CPU / 内存 / 交换 / 磁盘。
- **选择器**：一个键（或点一下底栏）弹出所有会话，按项目分组，带实时预览，输编号就跳过去。
- **侧栏**：贴在每个 Claude 右边，管「这个会话」的一切：它说过的每一轮（点一下主界面滚过去）、
  额度、它目录里没提交的文件、git / 文件弹窗、换账号。
- **换账号**：点一下，把这个会话换到另一个 Claude 账号接着聊；在干活的、有没发的字的不动，带队员的先收队。

全程鼠标能用，也有快捷键。状态靠 Claude Code 的 hooks 上报，不轮询、不刮屏。

---

## 适合谁：为什么做成这样

它是按一种具体的用法长出来的：**一个 Claude 账号管一个项目，账号下的每个会话担一个职位**
（算法、后端、前端、测试……），人只做判断。账号有用量上限，项目之间按账号分开，额度各算各的；
会话按职位分开，上下文不互相污染；人一次只能盯一个终端，所以要有东西告诉你「现在哪个在等你」。

如果你只开一两个 Claude，用不上它；同时开着好几个、甚至用着两个账号的，它就是为你做的。

## 背景：为什么要按账号和职位分

| 问题 | 不分的后果 | 这样分以后 |
|---|---|---|
| 单个账号有用量上限（5 小时 / 7 天两个窗口） | 一个项目跑得猛，别的项目一起被卡住 | 额度按账号各算各的，一个项目用光不影响另一个 |
| 一个会话什么都干，上下文越来越杂 | 改前端的时候带着一堆后端的历史，越来越慢、越来越不准 | 一个会话一个职位，上下文只装这一摊事 |
| 人一次只能盯一个终端 | 还是串行，只是打字的换成了 Claude | 人只处理「在等我」的那几个，其余自己跑 |
| 会话、账号会换、会重启 | 换个号、开个新会话，前面的来龙去脉就丢了 | 记忆写在文件里（规则、交接、日志），换号换会话都接得上 |

### 三层结构

```
              我（判断 · 拍板）
        只在「等我确认 / 等我回答」时被叫过去
                     │
     ┌───────────────┼───────────────┐
  账号 A          账号 B          （加一个账号）
  = 项目 1        = 项目 2         = 项目 3
     │               │
  会话 = 职位      会话 = 职位
  算法 / 后端 /    产品 / 前端 /
  前端 / 测试      评测 / 部署
     │               │
     └──── 共享记忆：项目规则 · 交接文件 · 研发日志 · 历史会话检索 ────┘
```

落到 tmux 上：

- **tmux session = 项目**（也就是一个账号在管的那一摊）。
- **tmux window / pane = 职位**。一个职位通常一个 window；用 Claude Code 的编队（agent teams）
  时，一个 window 里是一个领队加几个队员。
- **底栏 = 全局**：所有队伍谁在跑、谁做完了、谁在等人，任何窗口都看得到。
- **右侧侧栏 = 当前这个会话**：它说过的每一轮、它的额度、它所在目录的 git 状态、它用的账号。

## 用起来是什么样（一天的场景）

1. 早上打开 tmux，两个项目、十来个会话都还在（tmux 重启过也会恢复成原来的 Claude 会话，
   不是一堆空 shell）。
2. 给几个职位各派一件事，然后去盯自己最关心的那个。
3. 底栏亮了 `⏸`：某个会话在等确认。点一下底栏（或 `prefix + a`），直接跳过去，处理完回来。
4. 底栏的 `✔` 多了一个：有个会话做完了还没看。打开选择器，按编号跳过去看结果。
5. 在某个会话里想回头看「前面第几轮它说了什么」：点右边侧栏里那一轮，主界面滚过去。
6. 想看它改了什么：点侧栏上的 git 图标，在它的目录里弹出 lazygit；点外面就关。
7. 一个账号的 5 小时额度快用完了：在侧栏点 ⇄，这个会话换到另一个账号，接着原来的对话继续。
   窗口里带着队员的，会先让领队把队员收回来再换。

## 工具一览

| 你想知道 / 想做 | 看哪里 / 点哪里 | 怎么做到的 |
|---|---|---|
| 有没有会话在等我 | 底栏 `⏸ WAIT`（红底，带窗口名和等了多久）、提示音、系统通知 | Claude Code 的 hooks 自己上报状态，不刮屏、不轮询 |
| 所有会话现在各在干什么 | 底栏计数 `⏸ ✔ ▶ ✓`；选择器（`prefix + g` 或点底栏） | 状态文件 + 每个会话的对话记录 |
| 跳到某个会话 | 选择器里输编号 / 回车；`prefix + a` 直接去最该处理的那个 | tmux 原生跳转 |
| 这个会话前面说过什么 | 右侧侧栏：每轮一项，点一下主界面滚到那一轮的最终回复 | 读 Claude Code 写在本地的对话记录，只读 |
| `/compact` 前的轮次 | 侧栏顶上收成一行「#1–#290 已压缩」，点开展开 | 同上 |
| 它改了哪些文件 | 侧栏 git 图标（旁边是没提交的文件数）/ 文件夹图标 | lazygit / yazi 浮在右边，点外面就关 |
| 额度还剩多少 | 侧栏表头：上下文、5 小时、7 天三条，有问题才变色 | Claude Code 自己缓存的 `/usage` 数据 |
| 换账号 | 侧栏 ⇄（旁边是现在登的账号） | 退出 → 用另一个账号 `--resume` 同一个会话；在干活、有没发的字就不动 |
| 机器还撑不撑得住 | 底栏右下角 CPU / 内存 / 交换 / 磁盘，点开看是谁占的 | 不用 top，很快 |

状态只有四个，靠形状就能分辨：

| | 状态 | 意思 |
|---|---|---|
| `⏸` | WAIT | 在等你明确同意或回答。唯一会主动通知你的状态 |
| `▶` | RUN | 在干活，不用管 |
| `✔` | DONE | 做完了，你还没看 |
| `✓` | READ | 做完了，你也看过了 |

## 几个取舍

- **状态靠 hooks，不靠刮屏。** 会话自己在状态变化时上报，所以准、而且不耗资源。屏幕只在
  「跳到第几轮」「输入框里有没有没发的字」这类没有别的办法的地方才读。
- **是收件箱，不是仪表盘。** 看过的自动变 `✓`，不关心的可以归档；会话一有新动作，标记自动失效。
  列表自己保持短，不用人去维护。
- **全程鼠标也能用。** 底栏、选择器、侧栏的按钮都能点；习惯键盘的人照样有快捷键。
- **只跟当前会话有关的放侧栏，跟全局有关的放底栏。** git、文件、额度、换账号都是「这个会话」的事，
  所以在侧栏；底栏只留跨窗口的：各会话状态、整机资源。
- **换账号要安全。** 在干活的、等确认的、输入框里有没发出去的字的，一律不动；带队员的先收队。

## 已知限制（写进 README，别藏）

- **只在 macOS 上日常使用。** 通知、提示音、常驻进程（launchd）是 macOS 的；Linux 没测过。
- **界面是中文的。** 英文界面要另做（见 `PROMO.md` 的阶段二）。
- **有几处依赖 Claude Code 的界面长相**：侧栏「跳到第几轮」、换账号时认输入框，都要读屏幕。
  Claude Code 改版时可能要跟着改。
- **要 Nerd Font。** 侧栏和底栏的按钮是 Nerd Font 图标；终端里关掉「非 ASCII 字符用另一个字体」，
  否则图标会显示成问号。
- **换账号假定你有两个账号、各有一个配置目录**（`CLAUDE_CONFIG_DIR`）。

## 推广文章

**角度**：分享一个工具。主线是「这套工具能让你看到什么、少操多少心」；工作方式（账号分项目、
会话分职位）放在开头一两段当背景，交代它为什么做成这样，不展开成方法论。

标题备选（先挑一个，再按平台微调）：

1. 我给 Claude Code 写了一套 tmux 控制台：底栏、选择器、侧栏、一键换账号
2. 在 tmux 里带几支 Claude Code 团队：一个开源工具的分享
3. 让 Claude Code 自己报告「我在等你」：一套 tmux 工具

结构：

1. **一张图开场**：底栏 + 选择器 + 侧栏同屏的截图（或 GIF），一句话说它是什么。
2. **背景两段**：我怎么用 Claude Code（一个账号一个项目、一个会话一个职位，配框架图），
   于是碰到三个问题：不知道谁在等我、不知道大家在干什么、额度一用光就卡住。
3. **四块工具，各配一张图**：底栏（谁在等我）、选择器（大家在干什么）、侧栏（这个会话的一切）、换账号。
4. **几个取舍**：状态靠 hooks、收件箱不是仪表盘、只跟当前会话有关的放侧栏、换账号要安全。
5. **拿来用**：仓库地址、安装、已知限制。

渠道沿用 `PROMO.md` 的两阶段：先发中文（知乎、掘金、V2EX、小红书），英文界面做完再发英文（HN、Reddit）。
