# tmux 侧边轨迹改 Rust：要从 herdr 版搬哪些功能

2026-11-08。用户回到 tmux、关掉了 herdr，想把 tmux 侧边轨迹改成 Rust，并把 herdr 版（statetrail）里做过的产品设计搬过来。
这份是对照表和定下来的范围。

## 为什么改 Rust

| | tmux 版现在（Python + fzf） | herdr 版（Rust） |
|---|---|---|
| 常驻部分 | 一个 Python 后台管所有侧栏：13 个 Claude 时约 49MB、约 1–2% CPU，每秒醒 10 次看点击 | 没有共用后台 |
| 每个侧栏 | 一个 fzf，6–13MB | 一个小程序，约 7MB；有事件才醒，开 26 个空闲时合计 CPU 0% |

herdr 版的读对话记录、额度、画面、跳转这几块（`transcript.rs` `claude.rs` `render.rs` `jump.rs`）本来就和 herdr 无关，
改 tmux 版主要是换掉和 herdr 打交道的那一层（`pane.rs` `herdr.rs`），改成跟 tmux 打交道。

## 定下来的范围（2026-11-08 用户拍板）

用户原话：「除了你建议的…窄板和宽板，这个我还是要的，所以6要勾上。然后这个底部的按钮就不要了，因为这些底部的 Git 和文件按钮，
我已经在 tmux 的底部栏上已经集成了……我们已经集成在上方了，所以不管是上方还是下方……有个位置也都可以。对剩下的就按你自己定义的来吧。」

- **做**：1 分章、2 搜这个会话、3 搜所有会话、4 键盘操作、5 上下还有几轮、6 窄版 / 宽版、8 不在仓库里时先选仓库、
  10 只有正在看的那个才盯屏幕、11 换了新版本自己重启（我定的：开发时反复换代码用得上，成本低）。
- **不做**：7 可配置的底部按钮（Git、文件已经在侧栏表头的图标行里，位置在上在下都行，保持现状）；
  9 窗口用会话名命名（我定的：tmux 窗口名已经跟着 Claude 的终端标题走，不重复做）。
- **保住**第二节里 tmux 版独有的全部功能。
- **代码放哪**：statetrail 仓库，和 herdr 版并排加一个 tmux 版（它的 README 本来就写着「一个宿主一个插件」）；
  和宿主无关的几块（对话记录、额度、画面、跳转、分章、搜索）抽成两边共用，免得两份各改各的。
  Rust 版验证过之前，现在的 Python 侧栏照常在用，不删。

## 一、herdr 版有、tmux 版没有的

| # | 功能 | 一句话 | 建议 |

## 二、tmux 版有、herdr 版没有的（改 Rust 时要保住）

- **关闭按钮和自动打开**：窗口够宽（≥120 列）自动开，点 ✕ 关掉，关过的那个不再自动开。
- **侧栏上面的命令行**：默认 8 行，目录跟 Claude 一样，跟侧栏一起开关。
- **Git、文件用浮窗**：浮在右边，点 Claude 就关，Claude 的大小不变。和第 7 条二选一，或者做成配置项。
- **Git 按钮上的数字**：这个目录里没提交的文件数。
- **队友模式**：窗口里有 agent teams 的队友时，侧栏改成浮在右边，不挤领队。
- **tmux-resurrect 恢复后不留空壳**。
- **有侧栏的窗口，底栏不再重复画额度**。

## 三、两边都有的（照搬即可）

点一轮跳过去；主界面在看哪一轮（亮边）；`/compact` 之前的收成一行；「主界面已无」灰显、不白翻；
模型、账号、`ctx` `5h` `7d` 三条柱子（平时灰、超出匀速线才上色）和重置倒计时；点额度马上查一次；
就地换账号；跳到某个 Claude 的浮窗（herdr 版本来就是照 tmux 版 picker 做的）。

## 以后（侧栏 Rust 版稳定之后再说，现在不做）

2026-11-08 用户问其余 tmux 脚本要不要也改 Rust。按「跑得多频繁」排：
- **值得并进同一个 Rust 程序**：`hooks/tmux_status_update.py`（每次工具调用都起一个 python，约 20 毫秒）、
  `bin/status-badge.sh`（状态栏每 10 秒一次，内部调 3 处 python，每轮约 0.06 秒 CPU）。做成同一个程序的子命令，启动只要几毫秒。
- **不用改**：picker、总览、token 报表、切账号这些点了才跑的；`tmux-sysstat.sh` 本来就是纯 shell、很轻。
