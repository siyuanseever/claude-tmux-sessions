# 侧栏（sidebar）

> 原来是单独的仓库 claude-trail，2026-10-23 并进来。状态目录还叫 `~/.local/state/claude-trail`（开着的侧栏都往那里写，改名要一起迁）。

tmux 里贴在 Claude Code 窗格右边的多轮对话导航栏，全程用鼠标：每轮一项，
点一下，主界面的 Claude 就滚到那一轮的最终回复。

Claude Code 终端里只能一格一格往上滚，找每一轮的收尾总结，还怕漏掉中间的轮次。
这个侧栏读取 Claude Code 自己写在 `~/.claude/projects/*/*.jsonl` 里的对话记录，
把「每次 Claude 停下来」列成一行：你那一轮说的话 + Claude 回复的开头。

- **默认打开**：Claude 独占一个窗口、窗口够宽（≥120 列）时，你切到那个窗口就自动在右边开侧栏。
  `tmux set -g @trail_auto 0` 整体关掉自动打开
- **打开/关闭**：点 tmux 状态栏上的侧栏图标（右边带侧栏的窗口），或点侧栏表头的关闭图标（✕）。
  你关掉的那个 Claude 不会再被自动打开，直到你再点一次 `轨迹`
- **队友模式**：Claude Code 的队友（agent teams）在同一个窗口开了窗格时，领队被挤成左边一条，
  平铺的侧栏会先收起来（再切一块领队就没法看了）；这时点状态栏「轨迹」会开一个**浮在窗口右边**的侧栏，
  盖住队友那一侧的一部分、不挤领队，表头的「到最底」图标照样能用。队友都退出后平铺的侧栏自动回来
- **表头带上下文和额度**：模型/推理力度单独一行，后面跟着现在登录的账号（`Opus 5.5/high · you`，
  读 `~/.claude.json` 的 `oauthAccount`，按 mtime 缓存）——两个账号轮流 `/login`、额度各算各的，
  下面那两条柱子说的是谁的额度得看这里；窄到放不下就只留模型名。下面是 `ctx` / `5h` / `7d` 三条柱子，列对齐。
  实心 = 已经用掉的比例，蓝色竖线 = 那条参照线（额度是「窗口已经走过的时间」，上下文是
  「自动压缩的那条线」）：线在实心右边就是还有富余，被实心盖过去就是过了。
  **平时一律淡灰，快有问题了才上颜色**，所以颜色一出现就是信号。判据是「超出参照线多少」，
  不是用了多少 —— 5h 用掉 38%，在窗口第 3 小时是正常、在第 10 分钟是要命。
  超出匀速线 20 个百分点起橙、35 个起红，绝对值到 80%/93% 也分别橙、红；
  上下文过目标线八成橙、过线红（目标线取 settings.json 的 autoCompactWindow，改成 auto 了就按 50 万算）。
  柱子宽度按最长的那条尾巴反推、剩多少用多少；点 `5h` / `7d` 那两行马上去查一次真实用量。
  表头不写会话标题：侧栏就贴在那个 Claude 旁边，标题 tmux 的窗口名上已经有了
  这些原来在 tmux 底栏右边，一行只放得下两个字形、数字要点开才看得到；底栏在**有侧栏的窗口
  里就不画这一段**了（侧栏没开时照旧画，不会哪儿都看不到额度）
- **上面一条命令行**：侧栏上面切出一个 shell（默认 8 行，起始目录跟 Claude 那个窗格一样；侧栏列表点得多，放下面），
  要敲 `git` 看一眼、翻个文件不用离开这个窗口。`tmux set -g @trail_shell_height 12` 改行数，
  设 `0` 不开。跟侧栏同生共死：关侧栏它一起走，侧栏意外退出常驻进程也会把它收掉。
  队友模式下的浮动侧栏不切（浮窗再切一块更挤）
- **tmux-resurrect 恢复后不留空壳**：侧栏和它上面的命令行都打着 `@resurrect_skip`（常驻进程每轮补），
  `bin/resurrect_hooks.py` 存档时记下这两格、恢复完把恢复出来的空 shell 关掉，
  窗口里只剩 Claude 一格，常驻进程再照常开出真正的侧栏
- **列表**：按时间正序，打开时落在最后一轮；滚轮只滚列表，很快
- **`/compact` 之前的轮次收成一行**：列表最上面「#1–#290 已压缩（290 轮）· 点开展开」，表头写
  「290 轮已压缩 · 当前 15 轮」。主界面已经跳不过去，几百轮不压缩的会话压完以后，列表里几乎全是点了没用的项。
  点那一行展开（变成「点这里收起」），展开时点其中某一轮不会收回去
- **单击一项**：侧栏里把你那一轮说的话整段展开；主界面的 Claude 滚到那一轮，最终回复停在屏幕上方。再点同一项也会跳，
  主界面自己滚走了可以再点一次回来
- **表头第 2 行是一排图标**（Nerd Font，终端要用带图标的字体，这台是 HackNFM），从左到右：
  - 两个向下箭头：主界面回到最新处，并恢复自动跟随
  - git 标志 + 数字 / 打开的文件夹：在这个 Claude 所在的目录开 lazygit / yazi（`bin/float-tool.sh`）。
    数字是这个目录里没提交的文件数（`git status --porcelain` 的行数，常驻进程每个目录 10 秒查一次），
    不是仓库或都提交了就空着。弹窗浮在右边、会盖住侧栏，点左边的 Claude（弹窗外面）就关，回到侧栏。
    底栏不再有 `git` `文件`，只剩一个开关侧栏的图标
  - 刷新 + 一小段字：马上去查一次真实额度；后面紧跟着「15 分钟前」「刚刚更新」「查询中…」「查询失败」
  - ⇄ + 「l2」：把这个 Claude 换到另一个账号，后面写的是**现在**登的是谁（登录邮箱名里两个账号不一样的那截）。
    用的是 `bin/switch_account.py`：正在干活、输入框里有没发的字就不动；窗口里有队友就先让领队收队。
    切换中显示「…」，被拦下或失败显示「✗」（30 秒），原因在 tmux 底部那行。切换期间 Claude 退出重启那几秒，
    常驻进程不会把侧栏当成「Claude 没了」收掉
  - 叉：关掉侧栏

  每个按钮占 3 格（空格 + 图标 + 空格），git 和刷新后面的那段字按最长的情况留固定宽度，数字变了后面的按钮
  也不挪位；点偏一格、或点在后面那段字上都算点了这个按钮。只跟这个 Claude 有关的东西往侧栏上放，
  底栏留给跨窗口的（会话列表、整机 CPU / 内存）
- **自动刷新**：Claude 回复完、或你发了新消息，列表自己更新；Claude 还在干活的那一轮显示「还在干活…」
- 只读对话记录；对主界面只发滚动用的按键（`Ctrl+Home`/`Ctrl+End`/`PageUp`/`PageDown`/滚轮），
  不碰输入框里没发出去的字

## 依赖

- tmux 3.7+、fzf 0.74+（用到 `click-header`、`--id-nth`、`--listen`）、python3
- 常驻进程：`./install.sh` 装成 launchd 服务 `com.claude-tmux.sidebar`（开机自启、崩了自动拉起），
  日志 `~/.local/state/claude-trail/daemon.log`
- Claude Code 用全屏界面（`/tui fullscreen`），主界面跳转靠它的滚动快捷键
- 本仓库的 hook（`hooks/tmux_status_update.py`）：它在 `~/.claude/tmux-claude-status.json`
  里记每个窗格当前的 session_id 和运行状态，侧栏靠它知道该看哪个会话
- 状态栏按钮挂在 `bin/float-tool.sh` 上（`tool:trail` → `trail-sidebar.sh`）

## 文件

- `claude_trail.py` 解析对话记录，给侧栏提供 `rows` / `header` / `click` / `jump` / `bottom` /
  `sig` 几个子命令，参数都是 Claude 所在的 tmux 窗格。
  测试时可以用 `CLAUDE_TRAIL_TRANSCRIPT=<jsonl>` 指定读哪个会话
- `trail-sidebar.sh` 开关侧栏和它上面那条命令行；侧栏本体只有一个 fzf（exec，没有外壳进程，不轮询）
- `trail_daemon.py` 所有侧栏共用的常驻进程：盯对话记录、推刷新、点击展开、自动开关侧栏，
  以及额度旧了就去刷一次（这件事原来是底栏那段 `#(status-badge.sh quota)` 顺手做的，
  底栏不画它以后得有人接）

## 为什么这样设计

- **一个常驻进程管所有侧栏，只读新追加的行**：以前每个侧栏自带一个 bash 循环，每 2 秒起一次 python
  把整份对话记录从头解析一遍（最大的 150MB，一次 0.28 秒），开十个侧栏电脑就卡。现在每秒一次
  `tmux list-panes -a`，对话记录只 stat，变长了才读新的几行；没变化连列表都不重拼。
  实测 8 个侧栏：常驻进程约 32MB、约 2% 单核，每个侧栏的 fzf 6–13MB
- **不会莫名其妙退出**：以前一次 tmux 调用失败（机器很忙时会超时）就把侧栏关了。现在只有
  `list-panes` 成功、Claude 窗格确实没了（或连续 5 秒不是 Claude）才关；侧栏意外退出了会自动重开

- **没有预览窗**：以前侧栏下半部分显示那一轮的全文，但主界面能跳过去以后，它显示的和主界面
  一模一样，是多余的（用户原话：「它显示的内容和我主会话里的内容完全一样，所以它完全没有必要存在」）。
  排版代码（rich + 认识中文的断词）在 039dabb 及之前的版本里
- **滚轮只滚列表（`offset-up/down`），不挪选中行**：选哪一轮靠单击
- **只在列表看起来不一样时才刷新**，并且进行中的那一轮保持占位文字：Claude 干活时对话记录几乎一直在变
- **主界面跳转**：Claude Code 没有「跳到第几轮」的命令，只能像人一样滚着找。从离那一轮更近的一头
  开始（`Ctrl+Home`/`Ctrl+End`），每读一次屏幕翻两个半屏，看到最终回复开头的几个字就停，再往回微调
  到顶部。用 `PageUp/PageDown` 而不是滚轮：滚轮连续快发会加速，一下滚过头；每次翻页后等 Claude
  重绘完再读屏，读到半截画面会漏过去。以「❯」开头的行（你自己的消息）不算命中，你常会引用 Claude 的话
- **跳转挂在 `left-click` 上**：fzf 先把选中行挪到被点的那项、再执行绑定，所以 `{1}` 就是点中的那一轮；
  点表头走 `click-header`，不会触发。打开时落到最后一轮不算点击，不会带着主界面跳
- **表头按钮按列号识别**：`FZF_CLICK_HEADER_WORD` 按 `--delimiter`（Tab）切词，整行算一个词

## 已知限制

- `/compact` 之前的轮次，主界面里已经没有了（Claude Code 压缩后从压缩点重新显示）：
  默认收成一行，展开后列表里标「已压缩」，点了主界面会提示找不到。去掉预览窗以后，这些轮次的全文在侧栏里也看不到了
- 最后一两轮下面内容不够一屏时，主界面没法把它推到顶部，会停在偏下的位置
- 按文件顺序切轮：用过 `/rewind` 回退的会话，被放弃的分支也会列出来

## 主界面滚到哪了（位置指示）

- **侧栏里**：屏幕上正显示的轮次最左边一条亮边；表头写「主界面在 #a–#b」或「主界面在最底」。
- 认位置的办法和跳转一样：每轮最终回复开头那十来个字去屏幕上找（两边都去掉空白和 markdown 记号再比）。
- **翻不到的轮次**（续接的会话 Claude 只显示最近一段、/compact 清掉的）：第一次点它，翻到头发现没有，
  就把更早的一起记进 `~/.local/state/claude-trail/missing/<窗格>.json`；侧栏里灰显并写「主界面已无」，再点立刻提示，不再白翻。
